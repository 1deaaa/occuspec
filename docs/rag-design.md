# Agentic Metadata RAG 设计（docs/rag-design.md）

> 依据：对 `data-markdown/` 共 205 个 Markdown 的抽样调研（样本 11 份：GBZ 188—2025 主体、
> 诊断标准 GBZ37/49/68/70、采样规范 GBZ159、限值 GBZ2.1/GBZ2.2、设计卫生标准 GBZ1、
> 总则 GBZT300.1、金属烟热 GBZ48）。全部统计数字来自 `rg` 实测与文件读取，非推测。

## 1. 数据现状结论

1. 标题层级不可信：GBZ 188 把章、节、小节、表格全部压平为 `#`（`^# `=191，`^## `=4，`^### `=0）；
   诊断标准中新老混排（`## 4.1` 与 `# 5.1` 并存、无 `#` 纯文本章号并存）。**切分键必须是条款编号文本，而非 `#` 级别**。
2. 页码标记 `<!-- page N -->` 与封面页数一致（GBZ 188 共 139），但常在条款中间截断，
   **只做引用定位，不做切分边界**。
3. 附录标题携带性质字样（规范性/资料性），前言另有"附录 X 是规范性/资料性附录"声明句，
   两条规则可稳定判定附录类型。
4. 四类结论定义原文位于 GBZ 188 `4.8.2.2`（a 目前未见异常 / b 疑似职业病 / c 职业禁忌证 / d 其他疾病或异常），
   枚举值写死并引用该条款，禁止模型改写。
5. GBZ 188 单危害节结构固定：`X.Y.1 上岗前 / X.Y.2 在岗期间 / X.Y.3 离岗时 / X.Y.4 应急健康检查`，
   其下为"目标疾病 → 检查内容（必检/补充/选检）→ 周期"；在岗禁忌证多写"同 X.Y.1.1"，
   离岗内容多写"同 X.Y.2.2"，必须保留引用回链字段供检索时展开。
6. 两份 GBZ 188 文件（`GBZ 188—2025…` 与 `GBZ188-2025-…`）同为 9042 行，内容重复，入库去重只留一份。
7. 表格占比差异大：GBZ2.1 表格行占 38.4%，GBZ 188 仅 1.8%。限值表（尤其 GBZ2.1 表1）整表不切，另按物质行建索引。

## 2. 切分策略

- 主切分键（按条款号，不按 `#` 级别）：
  `^\s*(#{1,4}\s+)?(- )?\d+(\.\d+){0,3}\b`（章/条/款）
  `+ ^\s*(#{1,4}\s+)?(- )?[A-G]\.\d+(\.\d+)*`（附录）
  `+ ^\s*#{0,2}\s*表[A-Z]?\.?\d+` / `图G.1` 独立成块；
  `<!-- page -->` 与眉题只做属性。
- 二次切分阈值：单危害节（5.x/7.x）约 2–5k 字符可单块；若块 > 2500 字符或 > 120 行，
  按 `X.Y.1–.4`（上岗前/在岗/离岗/应急）再切；附录 E/F 一览表每表一块。
- 引用回链：块内"同 5.x.y.z""按 GBZ 37/49/260/325""参见附录 X"保留为 `relations` 字段，检索时展开。
- 验证：抽样 20 条人工检查切分与元数据抽取正确率（见 §5），错例写入本节附表。

## 3. 元数据字段

| 字段 | 来源 | 提取方法 |
|---|---|---|
| standard_code | 文件标题 `GBZ[\s　]*\d+(\.\d+)?—\d{4}` | 首屏正则，失败回退文件名 |
| clause_no | 条款编号文本 | 主切分键捕获组 |
| clause_title | 编号后同行文本 | 切分时截取 |
| appendix_type | 附录标题括号（规范性/资料性）+ 前言声明句 | 双规则判定 |
| page_no | 最近的上方 `<!-- page N -->` | 归因最近标记 |
| check_class | 必检/补充/选检关键词 | 块内关键词抽取 |
| target | 目标疾病/职业禁忌证行 | 块内关键词抽取 |
| period | `周期[：:].*年\|月` | 块内正则抽取 |
| force | 强制性/推荐性（前言"第 X 章为推荐性"） | 前言规则 + 附录 C 默认推荐性 |
| relations | 引用条款/标准号 | 块内正则抽取 |

危害因素映射：从 GBZ 188 第 5/6/7/8/9 章节名映射（如 5.1→铅、7.1→噪声），诊断标准按标题映射。

## 4. 向量存储

- Embedding 模型：Qwen3-Embedding-8B，经 SiliconFlow `dimensions=1024` 参数实测可用，
  输出 1024 维（默认 4096 维）。
- PG 表 `clause_embedding(id, clause_id, standard_code, chunk_text, embedding halfvec(1024), metadata jsonb)`，
  索引 `USING hnsw (embedding halfvec_l2_ops)`（已在 PG 18 + pgvector 0.8.1 实测建索引成功）。
- 为何不用 `vector(4096)`：pgvector 0.8.1 的 `vector` 类型 HNSW 上限 2000 维，
  直接建索引必报 `more than 2000 dimensions`；1024 维在上限内且检索质量满足条款召回需求。

## 6. Agent 工具集

判定 Agent 可调用的检索工具（详见 `server` 源码 `rag` 包）：

1. `clause_retrieve`：语义检索 + 元数据过滤（危害因素/标准号/附录类型），返回条款与评分。
2. `clause_fetch`：按 `(standard_code, clause_no)` 精确取条款原文与页码。
3. `clause_expand`：沿 `relations` 展开引用条款（如 GBZ 188 → GBZ 49）与"同 X.Y.Z"回链。
4. `hazard_route`：按危害因素列出适用标准与条款清单（元数据直查 + 向量召回两条路）。

每次调用记录决策日志（查了什么/过滤条件/命中数/是否二次检索），写入审计表供回放。
